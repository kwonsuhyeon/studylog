flyKNNG 배경지식 노트

Zhuoran Ji, Cho-Li Wang. Efficient Exact K-Nearest Neighbor Graph Construction for Billion-Scale Datasets using GPUs with Tensor Cores. ICS '22. doi:10.1145/3524059.3532368

논문 1~3절과 4.3절을 읽기 전에 필요한 GPU 기초를 정리했다. 2026-11-11 고성능 데이터마이닝 논문 발표 준비용.

수치와 인용은 원문 기준이다. 손 계산 예제는 이해를 돕기 위해 직접 만들었고, 원문에 없는 해석에는 추론이라고 적었다.

논문이 푸는 문제

🔊 듣기 A (1~3절)
데이터셋의 모든 점마다 가장 가까운 k개 이웃을 정확히 찾아 그래프(KNNG)로 잇는다. 점이 10억 개일 때 이 계산을 GPU의 Tensor Core로 빠르게 하는 방법이 flyKNNG다.

KNN, KNNG, exact

용어뜻
최근접 이웃 탐색 (NNS)질의 점 \(q\) 하나와 가장 비슷한(거리가 가장 작은) k개 점을 데이터셋에서 찾는 일. 원문 2.1절은 "모든 점과의 거리를 구한 뒤 top-k selection을 한다"고 정의한다.
k-최근접 이웃 그래프 (KNNG)데이터셋의 모든 점을 질의로 삼아, 각 점을 자기 k개 이웃과 간선으로 이은 그래프. 질의가 N개인 NNS라고 보면 된다.
정확한 KNNG (exact KNNG)근사 없이 모든 점 쌍의 거리를 계산해서 만든 KNNG. 이 논문이 만드는 그래프다.
근사 최근접 이웃 탐색 (ANNS)색인을 써서 일부만 보고 빠르게 찾는 방법. NSG·DPG 같은 그래프 기반 색인이 KNNG에서 출발한다.

정확한 KNNG가 왜 필요한지 원문 2.1절은 이렇게 설명한다. 그래프 기반 근사 색인의 품질은 처음 만든 KNNG의 품질에 달려 있고, 정확한 KNNG는 한 번 만들어 두면 여러 번 쓴다. 그래서 무차별 대입(brute-force)으로라도 정확하게 만들 가치가 있다.

비용이 큰 이유

N개 점이 각각 D차원이면 모든 쌍의 거리 계산은 \(O(N^2D)\)이다 (원문 3.1절). KNNG 구축은 두 단계로 나뉜다.

① 거리 행렬 계산

N×N개의 거리를 모두 계산한다. 계산량이 압도적으로 많다.

② top-k 선택

거리 행렬의 행마다 k개를 고른다. k는 작지만 행 전체를 한 번씩은 봐야 한다.

flyKNNG는 ①을 Tensor Core 행렬곱으로 계산하고, ②를 ①과 같은 커널 안에서 바로(on-the-fly) 처리한다. 원문은 이 두 알고리즘을 함께 설계(co-design)했다고 강조한다.

Tiling과 Tensor Core

🔊 듣기 B (4~6절)

논문 연결: 2.2절 Tensor Core Unit, Figure 1 tile-major layout, 3.3절 타일 크기.

큰 행렬을 작은 조각(타일)으로 나눠 빠른 메모리에 올려 두고 여러 번 쓴다(데이터 재사용). Tensor Core는 그 작은 행렬곱을 한 번에 처리하는 전용 장치다.

행렬곱 한 칸 = 행 · 열

\(A=\begin{bmatrix}1&2\\3&4\end{bmatrix},\ B=\begin{bmatrix}5&6\\7&8\end{bmatrix}\)이면 \(C=AB=\begin{bmatrix}19&22\\43&50\end{bmatrix}\). 첫 칸은 \(C_{0,0}=1\times5+2\times7=19\)이다.

\(C_{0,0}=A_{0,0}B_{0,0}+A_{0,1}B_{1,0}\), \(C_{0,1}=A_{0,0}B_{0,1}+A_{0,1}B_{1,1}\)을 보면 \(A_{0,0}\)과 \(A_{0,1}\)이 두 번씩 쓰인다. 이 값을 global memory에서 매번 다시 읽지 않고 shared memory나 register에 두고 다시 쓰는 것이 데이터 재사용(data reuse)이다.

Tiling

행렬이 크면 전부 빠른 메모리에 올릴 수 없다. 타일 단위로 잘라 한 타일씩 올리고, 올린 타일로 할 수 있는 계산을 최대한 몰아서 한다. 차원 방향도 잘라서 부분 곱을 누적한다.

$$C_{\text{tile}} = A_1B_1 + A_2B_2 + A_3B_3 + \cdots$$

Tensor Core와 MMA

Tensor Core(원문 표기 TCU, Tensor Core Unit)는 작은 행렬 두 개를 곱해 누적 행렬에 더하는 MMA(Matrix Multiply-Accumulate)를 수행한다.

$$D = A\times B + C$$
항목원문 2.2절 내용
한 클록에 하는 MMATuring \(4\times4\times4\), Ampere \(4\times8\times4\) (\(m\times k\times n\))
쓰는 방법cuBLAS 같은 라이브러리, 또는 warp 단위 C++ MMA API (load / store / mma)
API 최소 크기float16일 때 \(16\times16\)
결과가 놓이는 곳\(16\times16\) 행렬이 warp의 thread 32개가 가진 vector register 8개에 흩어져 저장됨

\(16\times16=256\)개 값을 thread 32개가 나눠 가지면 thread당 8개다. 이 8개가 어떤 순서로 놓이는지가 tile-major layout(원문 Figure 1의 이름)이다. 결과 행렬을 \(8\times8\) 타일 네 개로 나누고, vector register 두 개가 타일 하나를 맡는다 (예: R0과 R1이 왼쪽 위 타일). 행 우선(row-major)도 열 우선(column-major)도 아닌 이 배치 때문에 4절의 top-k 알고리즘이 따로 필요해진다.

원문은 NVIDIA 공식 문서가 이 배치를 명시하지 않았고 앞으로 바뀔 수 있다고 밝힌다. 그래도 타일 행렬곱의 관행 때문에 비슷한 배치가 유지될 것이라고 본다 (2.2절).

거리 계산을 행렬곱으로

논문 연결: 3.1절 Distance Matrix Calculation with TCUs.

모든 점 쌍의 내적은 행렬곱 \(XX^\top\) 한 번으로 나온다. 유클리드 거리와 코사인 유사도도 가벼운 전처리를 하면 이 내적으로 바뀐다. 덕분에 거리 계산을 Tensor Core에 맡길 수 있다.

기호표

기호뜻예제 값
\(N\)점 개수3
\(D\)차원 수2
\(P_i\)i번째 점 (길이 D 벡터)\(P_1=(1,2), P_2=(3,4), P_3=(5,6)\)
\(X\)점을 행으로 쌓은 \(N\times D\) 행렬\(3\times2\)
\(S_{ij}\)\(P_i\cdot P_j\), 내적. \(S=XX^\top\)\(S_{12}=11\)
\(q_i\)\(\|P_i\|^2\), i번째 점의 길이 제곱 (미리 한 번 계산)\(q=(5,25,61)\)
\(D^2_{ij}\)\(P_i\)와 \(P_j\) 사이 거리의 제곱\(D^2_{12}=8\)

원문은 내적 유사도를 \(d[i,j]\), 유클리드 거리 제곱을 \(d^2[i,j]\)로 쓴다. 이 노트의 \(S_{ij}\)가 원문의 \(d[i,j]\)에 해당한다.

내적 행렬 \(S=XX^\top\)

STEP 1 \(X=\begin{bmatrix}1&2\\3&4\\5&6\end{bmatrix}\), \(X^\top=\begin{bmatrix}1&3&5\\2&4&6\end{bmatrix}\)

STEP 2 \(S_{12}=P_1\cdot P_2=1\times3+2\times4=11\). 같은 방법으로 모든 칸을 채우면

$$S=XX^\top=\begin{bmatrix}5&11&17\\11&25&39\\17&39&61\end{bmatrix}$$

\(S\)의 i행 j열이 \(P_i\)와 \(P_j\)의 내적이다. 원문 3.1절은 이를 "essentially matrix multiplication"이라고 쓴다. 행렬곱으로 바꿔도 곱셈 수는 같다. 대신 Tensor Core와 Tiling을 쓸 수 있는 형태가 된다.

유클리드 거리 → 내적

\((a-b)^2=a^2+b^2-2ab\)를 차원마다 적용하고 같은 종류끼리 모으면 다음 항등식이 된다. 근사가 아니라 정확히 같은 값이다.

$$\|P_i-P_j\|^2 = \|P_i\|^2+\|P_j\|^2-2\,P_i\cdot P_j \quad\Longleftrightarrow\quad D^2_{ij}=q_i+q_j-2S_{ij}$$

STEP 3 \(P_1=(1,2), P_2=(3,4)\): \(q_1=1+4=5\), \(q_2=9+16=25\), \(S_{12}=11\)

STEP 4 \(D^2_{12}=5+25-2\times11=8\). 직접 구해도 \((1-3)^2+(2-4)^2=4+4=8\)로 같다. 실제 거리는 \(\sqrt8\approx2.83\).

STEP 5 세 점 전체: \(D^2=\begin{bmatrix}0&8&32\\8&0&8\\32&8&0\end{bmatrix}\). 대각선 0은 자기 자신이고, KNNG에서는 보통 뺀다.

\(q_i\) 계산은 \(O(ND)\), 내적은 \(O(N^2D)\)이다. 무거운 쪽인 내적만 Tensor Core로 보내면 된다 (원문 3.1절 "trivial pre-processing cost"). 제곱근은 크기 순서를 바꾸지 않으므로 순위를 정할 때는 \(D^2\)만 있으면 된다.

코사인 유사도: 모든 점을 길이 1로 정규화하면 코사인 유사도가 곧 내적이다 (3.1절).

Q. \(X\)가 1,000,000 × 128이면 \(XX^\top\)의 크기는?
연습: \(P_1=(2,3), P_2=(4,5)\)일 때 \(q_1\), \(S_{12}\), \(D^2_{12}\)는?

\(q_1=4+9=13\), \(q_2=16+25=41\), \(S_{12}=8+15=23\), \(D^2_{12}=13+41-46=8\). 확인: \((2-4)^2+(3-5)^2=8\).

Top-k의 방향

논문 연결: 2.3절 "only sorts the k largest distances", 4.2절 top-k 내림차순 불변식, 4.3절 pruning 조건.

이 논문에서 top-k는 값이 가장 큰 k개를 뜻한다. 원문은 거리 행렬을 내적 유사도로 정의하므로 값이 클수록 가깝다. 발표에서 "가장 작은 거리 k개"와 섞어 쓰지 않도록 주의한다.
원문 위치문장 (요지)방향
3.1절\(d[i,j]=P_i\cdot P_j\) (dot product similarity)로 거리 행렬을 정의클수록 가까움
2.3절KNNG에는 "k largest distances"만 정렬하는 partial sorting이 적합큰 값 k개
4.2절topk는 항상 내림차순. 짧은 쪽을 +∞(topk 앞)·−∞(outC 끝)로 채움큰 값 k개
4.3절지금까지 본 top-k 중 가장 작은 값보다 작으면 top-k가 될 수 없으므로 건너뜀큰 값 k개

유클리드 거리는 어떻게 맞추나 (추론)

원문은 유클리드 거리도 "trivial pre-processing"으로 행렬곱이 된다고만 쓰고, 부호를 어떻게 바꾸는지는 적지 않았다. 다음은 직접 정리한 한 가지 방법이다.

행 i를 고정하면 \(q_i\)는 모든 후보에 같으므로 순위에 영향이 없다. 그러면

$$D^2_{ij}\ \text{가 작은 순서} \;=\; 2S_{ij}-q_j\ \text{가 큰 순서}$$

예 \(P_1\) 기준: \(P_2\)는 \(2\times11-25=-3\), \(P_3\)는 \(2\times17-61=-27\). \(-3\)이 더 크고, 실제로 \(D^2\)도 8 < 32로 \(P_2\)가 더 가깝다.

발표 질의응답 대비: 원문 실험(5절)이 어떤 거리 척도를 썼는지, 이런 변환을 했는지는 실험 절을 읽을 때 다시 확인한다.

분리형 vs 융합형 (3.2절)

분리형의 장점

각 커널을 따로 최적화하기 쉽다. 거리 계산에 cuBLAS GEMM을 그대로 쓸 수 있다.

분리형의 문제 (원문)

거리 행렬을 global memory에 썼다가 다시 읽는 불필요한 접근이 두 번 생긴다. 거리 행렬이 GPU 메모리를 차지해 데이터셋에 쓸 공간이 줄고, mini-batch 수와 전송량이 늘어난다.

Figure 2: warp 하나가 행 여러 개를 끝까지 맡는다

top-k를 고르려면 한 행의 값을 전부 봐야 한다. 그래서 flyKNNG는 거리 행렬의 같은 행들을 같은 warp에 배정한다. warp는 데이터셋을 batch 단위로 돌며(itr 0, itr 1, …) 거리를 계산하고 top-k를 유지한다.

원문은 이 배정이 행렬곱만 보면 최선이 아닐 수 있다고 인정한다. 대신 top-k 선택에서 warp 사이 통신이 생기지 않아 전체 처리량이 오른다 (3.2절). co-design의 첫 번째 예다.

Q. flyKNNG가 on-the-fly top-k를 쓰는 가장 중요한 이유는?

Warp Shuffle · Warp Divergence · Pruning

논문 연결: 4.1절 Algorithm 2의 shuffle_reg, 4.3절 Warp-grained Top-k Selection Pruning.

top-k 갱신을 거리 계산과 같은 커널에서 하려면 세 가지가 필요하다. thread끼리 register 값을 빠르게 주고받고(shuffle), 모든 thread가 같은 길로 실행되게 하며(divergence 회피), 필요 없는 갱신은 warp 통째로 건너뛰는 것(pruning)이다.

Warp Shuffle

thread 0의 register 값 8과 thread 1의 register 값 3을 비교·교환하고 싶다. register는 자기 thread 전용이라 직접 읽을 수 없다. CUDA의 __shfl_sync() 계열 명령은 같은 warp 안에서 shared memory를 거치지 않고 register 값을 건네준다. 이를 warp shuffle이라고 한다.

tmp = shuffle_reg(R[i], off);              // 짝이 되는 thread의 값을 받아 옴 (예: shfl_xor_sync)
vec_cas(R[i], tmp, isDec ^ (tid & off));   // compare-and-swap: 비교해서 내가 가질 값을 남김

원문 4.1절: shuffle은 가장 효율적인 통신 수단 중 하나지만 통신이 없는 것보다는 비싸다. 그래서 Algorithm 2는 shuffle 횟수가 최소가 되도록 설계되었다 (정렬 대상 register 수와 상관없이 bitonic 수열 만들기에 1번, 정렬에 2번).

Warp Divergence

warp의 32개 thread는 같은 순간에 같은 명령을 실행한다. if (value > 5)에서 일부는 참, 일부는 거짓이면 GPU는 참인 쪽을 실행하는 동안 거짓인 쪽을 쉬게 하고, 그다음 반대로 한다. 이런 현상을 warp divergence라고 한다.

원문 2.3절은 heap이나 merge queue 같은 기존 top-k 자료구조가 비교마다 분기를 만든다고 지적한다. 분기가 많으면 제어 흐름이 복잡해지고, 컴파일러가 명령을 파이프라이닝해 ILP(명령 수준 병렬성)를 높이기 어렵다. bitonic sort는 비교할 위치가 값과 상관없이 미리 정해져 있어서 모든 thread가 같은 명령을 실행한다 (4.1절 "no warp divergence is incurred").

Warp-grained Pruning (4.3절)

top-4(큰 값 4개)가 [95, 88, 76, 70]이면 가장 작은 후보는 70이다.

새로 계산된 값70보다 큰 값처리
[12, 35, 48, 62]없음warp 전체가 top-k 갱신을 건너뜀
[12, 35, 82, 62]82갱신 수행 (bitonic 정렬·병합)

원문은 이 판정을 값 하나하나가 아니라 한 iteration에서 warp가 계산한 거리 행렬의 위쪽 절반 또는 아래쪽 절반 전체 단위로 한다 (Algorithm 3 4행). 이유는 두 가지다. GPU는 SIMD 방식이라 thread마다 다른 결정을 하면 divergence가 생기고, bitonic 선택은 입력 크기가 2의 거듭제곱이어야 한다.

잃는 것

thread별 insertion queue처럼 값마다 판정하면 더 많이 걸러 낸다.

얻는 것

분기가 값 하나당 heap \(\log k\)개, insertion queue \(k\)개인데 Algorithm 3은 \(1/128\)개다. 분기가 적으니 거리 계산의 ILP를 해치지 않는다.

3.3절과 이어지는 부분: 한 iteration에 계산하는 거리 수(n 방향 타일)가 작을수록 "전부 탈락"일 확률이 높아진다. flyKNNG의 타일 설계에서는 데이터 재사용을 해치지 않고도 n을 작게 둘 수 있다.

Q. pruning을 warp 단위로 판정하는 이유는?

Algorithm 1 한 줄씩

🔊 듣기 D (9~10절)

논문 연결: 3.3절 Kernel Design and Analysis, Algorithm 1. 원문은 shared memory double buffer 같은 최적화를 빼고 단순화했다고 밝힌다. 각 줄은 thread가 아니라 warp 기준이다.

1:  L_TCU = matrix size of tensor cores
2:  matrixA = matrixB = dataset
3:  id_block = thread_block.id + offset for this kernel launch
4:  A_cached = cooperate_load(matrixA[id_block × m : +m][0 : +D])
5:  for iter in # of data items, step = L_TCU do
6:      B_cached = cooperate_load(matrixB[iter : +L_TCU][0 : +D])
7:      initialize C to zero matrix
8:      for d in 1...D, step = L_TCU do
9:          A = A_cached[warp_id × L_TCU : +L_TCU][d : +L_TCU]
10:         B = B_cached[d : +L_TCU]
11:         C = tcu_mma(A, B, C)
12:     topk[0 : k] = find_local_topk(C, topk[0 : k])
줄하는 일메모리
1Tensor Core가 한 번에 다루는 행렬 크기. 이 노트 예제에서는 16으로 둔다.—
2A와 B는 같은 데이터셋이다. A는 이웃을 찾을 점(행), B는 비교 대상(열)이라는 역할만 다르다.global
3block 번호 + offset. GPU가 한 번에 띄울 수 있는 block 수에 한계가 있어 커널을 여러 번 띄우고, 그때마다 offset만큼 A 위치를 옮긴다.—
4block의 thread들이 협력해 A의 점 m개(모든 차원)를 올린다. 이후 모든 iteration에서 재사용한다.shared
5바깥 반복 iter: 비교 대상 B를 L_TCU개 점씩 옮겨 간다.—
6이번 B 타일(점 L_TCU개)을 올린다.global → shared
7결과 누적용 C를 0으로.register
8안쪽 반복 d: 차원을 L_TCU씩 나눠 부분 내적을 누적한다.—
9–10이 warp가 맡은 A의 16행 중 d 구간, B의 d 구간을 꺼낸다.shared
11Tensor Core MMA: \(C\leftarrow A\times B+C\)register
12완성된 C(내적 값)로 top-k를 갱신한다. C는 global memory에 쓰지 않는다. 세부는 Algorithm 3.register

iter와 d는 다른 축이다

예 (직접 만든 예) 점 1,000개, 128차원, L_TCU = 16이라 하자.

  • iter: 어떤 점들과 비교할지. B를 P1~P16 → P17~P32 → … 로 옮긴다. A(이 warp의 16개 점)는 그대로다.
  • d: 그 점들의 128개 성분을 어떻게 나눌지. \(128\div16=8\)번 MMA를 누적하면 16×16 내적 블록이 완성된다.

3.3절이 설명하는 설계 선택

선택원문의 이유
A 타일을 shared memory에 둠warp가 B를 돌며 같은 A 행과 계속 곱하므로 A를 한 번만 올리면 된다.
B 방향(n) 타일을 작게block 안에서 B는 재사용되지 않으므로 작아도 처리량이 떨어지지 않는다. 남는 shared memory를 A에 주면 block 하나가 더 많은 점을 맡아 block 수와 global 접근이 준다. pruning 성공 확률도 오른다.
outer-product 방식을 쓰지 않음tall-and-skinny 행렬곱에는 보통 좋지만 register를 더 쓴다. top-k도 register에 있어서 register가 가장 귀한 자원이다.
A를 register에, top-k를 shared에 두는 반대 배치는 쓰지 않음이론상 가능하지만 더 느렸다. top-k는 읽기·쓰기가 잦고, A는 한 번 쓰고 읽기만 한다.
