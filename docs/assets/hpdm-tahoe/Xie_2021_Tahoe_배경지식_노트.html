Zhen Xie, Wenqian Dong, Jiawen Liu, Hang Liu, Dong Li. Tahoe: Tree Structure-Aware High Performance Inference Engine for Decision Tree Ensemble on GPU. EuroSys '21. doi:10.1145/3447786.3456251

논문 2~6절을 읽기 전에 필요한 개념 10개를 정리했다. 결정트리 학습(지니·엔트로피·가지치기)은 안다고 보고, 학습이 끝난 트리로 예측하는 추론을 GPU에서 빠르게 하는 데 필요한 것만 다룬다. 논문 자체의 설계 설명은 논문 해설에 있다.

수치와 인용은 원문 기준이고 근거는 서재 블록 id([c04#b003] 형식)로 적었다. 손 계산 예제 가운데 직접 만든 것은 제목에 "(직접 만든 예)"를 붙였고 Python으로 검산했다. 원문에 없는 해석에는 추론을 붙였다.

기존 FIL은 트리가 어떻게 생겼든, 데이터가 무엇이든 한 가지 저장 형식(reorg)과 한 가지 추론 전략(shared data)으로 추론했다. Tahoe는 트리의 구조와 통계를 보고 저장 순서를 바꾸고, 상황에 맞는 추론 전략을 스스로 골라 쓰는 추론 엔진이다.

Tahoe는 네 전략 중 하나의 이름이 아니라 아래 세 가지를 묶은 시스템의 이름이다. 실험에서 말하는 Tahoe의 성능은 재배치를 적용하고 성능 모델이 고른 전략으로 돌린 결과다.

결정트리 추론과 앙상블

🔊 듣기 A (1~3절)

원문 1절 [c03#b003], 2절 Decision tree and ensemble [c04#b003] [c04#b005]

결정트리 추론(decision tree inference)은 루트(root)에서 출발해 "속성 \(x_j\) < 임계값 \(b_i\)?"를 묻고 한쪽 자식으로 내려가기를 리프(leaf)에 닿을 때까지 반복하는 일이다. 앙상블(ensemble)은 트리 여러 개의 결과를 합쳐 최종 예측을 낸다.

수업에서 배운 결정트리는 학습 쪽 이야기였다. 지니 지수나 엔트로피로 어떤 속성을 어떤 값에서 나눌지 정하고, 가지치기로 트리를 줄였다. Tahoe는 학습이 끝난 트리를 받아서 새 샘플의 예측값을 빨리 내는 추론만 다룬다.

숫자로 따라가기 (직접 만든 예)

아래 트리는 비교를 최대 세 번 하는 작은 트리다. 이 예에서는 비교가 참이면 왼쪽, 거짓이면 오른쪽으로 간다. 샘플은 \(s = (x_1{=}6,\ x_2{=}2,\ x_3{=}0.7,\ x_4{=}\text{없음})\)이다.

\(x_1\)~\(x_4\)는 샘플 하나가 가진 속성 값이고, 아래첨자는 비교 순서가 아니라 속성 번호다. 어떤 속성을 볼지는 노드마다 적혀 있어서, 지나가지 않은 노드의 속성은 끝까지 읽지 않는다.

STEP 1 루트에서 \(x_1 = 6\)을 5와 비교한다. \(6 < 5\)는 거짓이므로 오른쪽으로 간다.

STEP 2 \(x_3 = 0.7\)을 0.5와 비교한다. 거짓이므로 다시 오른쪽이다.

STEP 3 \(x_4\)를 봐야 하는데 샘플에 값이 없다. 노드에 적힌 기본 경로 \(D\)(왼쪽)를 따라 리프 D에 닿는다. 노드는 세 번 읽었고 비교는 두 번 했다. 샘플 \(s\)는 \(x_2\)를 한 번도 보지 않았다.

다른 샘플 \(s' = (x_1{=}3,\ x_2{=}4,\ \dots)\)는 왼쪽 → 오른쪽으로 두 번 만에 리프 B에서 끝난다. 같은 트리라도 샘플마다 거치는 노드와 단계 수가 다르다. GPU 스레드 여러 개가 이 일을 동시에 하면 각자 다른 주소를 읽고 끝나는 시점도 다르다. 이것이 원문 1절이 말하는 불규칙한 메모리 접근과 부하 불균형의 출발점이다 [c03#b004] [c03#b005].

트리 세 개의 결과 합치기 (직접 만든 예)

원문은 개별 트리의 예측을 "결합해" 최종 예측을 만든다고만 적는다 [c03#b003]. 결합 방식은 앙상블 종류에 따라 다르다 추론. 랜덤 포레스트(random forest, RF)는 트리를 서로 독립으로 만들고, GBDT(Gradient Boosting Decision Trees)는 앞 트리의 오차를 다음 트리가 줄이도록 차례로 만든다 [c10#b002] [c10#b003].

RF 분류 (리프 = 클래스)101다수결1
RF (리프 = 클래스 1 확률)0.90.40.7평균 \((0.9+0.4+0.7)/3\)0.667
GBDT (리프 = 점수)+0.30−0.10+0.25합 \(0.30-0.10+0.25\)0.45

GBDT의 합 0.45는 확률이 아니라 범위 제한이 없는 점수다. 트리 값을 더하다 보면 3.2도, −1.7도 나온다. 이진 분류라면 이 점수를 시그모이드(sigmoid) 함수에 넣어 0과 1 사이의 확률로 바꾼다 추론.

$$ \sigma(z) = \frac{1}{1 + e^{-z}}, \qquad \sigma(0.45) = \frac{1}{1 + e^{-0.45}} = \frac{1}{1 + 0.638} \approx 0.611 $$

클래스 1일 확률이 약 61%라는 뜻이고, 0.5를 넘으므로 클래스 1로 분류한다. 점수가 0이면 확률은 정확히 0.5다. 점수가 양수로 클수록 1에, 음수로 클수록 0에 가까워진다(\(\sigma(3) \approx 0.953\), \(\sigma(-3) \approx 0.047\)). RF는 리프에 처음부터 확률이 적혀 있어 평균만 내면 되고, 이 변환이 필요 없다.

어느 쪽이든 트리마다 나온 값을 하나로 모으는 단계가 있다. GPU에서는 트리를 여러 스레드가 나눠 맡으므로 이 모으는 단계가 6절의 리덕션이 된다.

원문 8절은 GBM 계열이 얕은 트리를 많이, RF가 깊은 트리를 적게 쓰는 경향이 있다고 적는다 [c10#b003]. 실험에 쓴 15개 포레스트는 트리 8개(HOCK)부터 3000개(Higgs)까지, 최대 깊이 3(covtype)부터 20(gisette)까지 다양하다 [c09#b008].

간선 확률과 노드 확률

원문 2절 [c04#b003], 4.1절 노드 재배치 [c06#b006] [c06#b007], 4.2절 SimHash 가중치 [c06#b016]

간선 확률(edge probability)은 어떤 간선을 지나갈 확률이고, 노드 확률(node probability)은 루트부터 그 노드까지 간선 확률을 모두 곱한 값이다.

원문은 학습이 끝난 뒤 각 간선이 선택될 확률을 계산해 두고 Tahoe가 추론 때 쓴다고 적는다 [c04#b003]. Algorithm 1의 마지막 줄도 "추론 중 간선 확률 집계"다 [c08#b028]. 그 노드에 도착한 샘플 가운데 왼쪽으로 간 비율을 세면 간선 확률이 된다. 예를 들어 루트에 도착한 100개 중 80개가 왼쪽으로 갔다면 왼쪽 간선 확률은 0.8이다 추론.

GPU 메모리는 한 줄짜리 배열이라 트리도 노드를 일렬로 늘어놓아 저장한다. FIL(NVIDIA RAPIDS Forest Inference Library)이 쓰는 reorg 형식(reorg format)은 각 트리를 너비 우선 순서(breadth-first order)로 두되, 여러 트리의 같은 자리 노드를 번갈아 끼워 넣는다.

너비 우선 순서는 루트, 2층 왼쪽, 2층 오른쪽, 3층 왼쪽부터 차례로 적는 방식이다. 트리 하나만 있으면 이것으로 끝이다. 트리가 여러 개일 때 reorg 형식은 "모든 트리의 루트 → 모든 트리의 2층 왼쪽 노드 → 모든 트리의 2층 오른쪽 노드 → …" 순으로 저장한다 [c04#b006]. 비어 있는 자리는 NULL로 채운다.

부하 불균형(load imbalance)은 스레드마다 맡은 일의 양이 달라 일찍 끝난 스레드가 기다리는 상태다. 원문은 스레드별 실행 시간의 변동계수(coefficient of variation, CV = 표준편차 ÷ 평균)로 그 정도를 잰다.

FIL은 트리를 라운드 로빈(round-robin)으로 스레드에 나눈다. 트리 깊이는 보지 않는다 [c05#b006]. 학습할 때 속성을 무작위로 고르고 사후 가지치기(post-pruning)를 하면 트리 깊이가 제각각이 되므로 깊은 트리를 받은 스레드가 더 오래 일한다 [c03#b005]. 수업에서 배운 가지치기가 여기서는 추론 속도 문제로 이어진다.

STEP 1 ijcnn1 포레스트(트리 10개, 깊이 6). 트리 하나 \(63 \times 8 = 504\)바이트, 포레스트 전체 5,040바이트. 48KB 안에 들어가므로 shared forest가 가능하다. 원문도 ijcnn1을 shared forest가 적용되는 다섯 데이터셋에 넣었다 [c07#b017].

STEP 2 Higgs 포레스트(트리 3000개, 깊이 8). 트리 하나 \(255 \times 8 = 2{,}040\)바이트, 포레스트 전체 6,120,000바이트(약 5.8MB). 들어가지 않는다.

STEP 3 그래서 쪼갠다. 한 조각에 트리 \(\lfloor 49{,}152 / 2{,}040 \rfloor = 24\)개, 조각 수 \(P = \lceil 3000/24 \rceil = 125\). 블록 125개가 조각 하나씩 맡고, 배치 하나가 끝나면 125개 결과를 전역 리덕션으로 합친다.

SimHash

원문 4.2절 Tokenization·Applying SimHash [c06#b014] [c06#b016] [c06#b023], Figure 3 [c06#b021]

SimHash는 트리 하나를 짧은 비트열(체크섬, checksum)로 요약한다. 토큰마다 해시 비트열을 만들고, 비트 0과 1을 −1과 +1로 보고 가중치를 곱해 위치별로 더한 뒤, 부호만 남긴다.

Tahoe가 트리 재배치를 하려면 어떤 트리끼리 비슷한지 알아야 한다. 원문이 말하는 "비슷하다"는 추론 때 비슷한 경로를 지나고 비슷한 속성을 읽는다는 뜻이다 [c06#b011]. 트리를 쌍마다 비교하면 트리 3000개에서 최대 19분이 걸려 온라인으로 쓸 수 없다 [c06#b012]. 그래서 트리마다 체크섬을 한 번만 만들고 체크섬끼리 비교한다.

지역 민감 해싱 (LSH)

원문 4.2절 Applying LSH [c06#b018], An example [c06#b024], Complexity analysis [c06#b020] [c06#b022], Figure 3

지역 민감 해싱(Locality Sensitive Hashing, LSH)은 비슷한 입력이 같은 해시값을 받도록 만든 해싱이다. Tahoe는 정규화한 체크섬을 청크(chunk) \(M\)개로 나눠 청크마다 해시하고, 같은 해시값이 나온 횟수(충돌 수)가 많은 트리끼리 메모리에 나란히 놓는다.

일반 해시는 입력이 한 비트만 달라도 결과가 완전히 달라지게 만든다. LSH는 반대로 비슷한 입력이 충돌하기를 바란다. 원문은 청크 해시로 Rabin-Karp 해싱을 쓴다 [c06#b018]. Rabin-Karp 해시는 문자열을 어떤 밑(base)의 자릿수로 보고 값을 계산하므로 같은 청크는 언제나 같은 값을 받는다. 2비트 청크에 밑 2를 쓰면 "01"은 1, "11"은 3이 된다 추론.
