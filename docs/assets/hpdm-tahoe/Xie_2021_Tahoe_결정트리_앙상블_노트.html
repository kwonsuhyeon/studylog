결정 트리 앙상블 노트: random forest와 GBDT

Tahoe 논문(Xie et al., EuroSys '21) 발표 준비용 · 광고 클릭 예측 예시로 따라가기

포레스트와 앙상블은 같은 말인가

Tahoe 논문 안에서는 같은 말이다. 논문 2절이 "ensemble"과 "forest"를 구분 없이 쓴다고 직접 밝힌다. 발표에서도 둘을 같은 뜻으로 써도 된다.

논문 밖에서는 범위가 조금 다르다.

용어뜻예
앙상블 (ensemble)모델 여러 개의 예측을 합쳐 쓰는 방식 전체. 트리가 아닌 모델을 묶어도 앙상블이다.트리 여러 개, 신경망 여러 개
포레스트 (forest)결정 트리로 이루어진 앙상블. 트리가 모여 있어서 붙은 이름이다.random forest, GBDT로 만든 트리 묶음
random forest포레스트를 만드는 학습 방법 가운데 하나의 이름.4절

헷갈리기 쉬운 곳은 "forest"와 "random forest"다. Tahoe 논문 Table 2는 GBDT로 학습한 트리 묶음도 forest라고 부른다. 그래서 이 논문에서 "포레스트"는 random forest만 가리키지 않고, 학습 방법과 상관없이 추론에 쓰는 트리 묶음 전체를 가리킨다.

예시 데이터: 광고 클릭 예측

광고 시스템은 사용자에게 광고를 보여 주기 전에 "이 사용자가 이 광고를 클릭할 확률"을 계산한다. 이 노트는 아래 표를 끝까지 예시로 쓴다. 수치는 설명하려고 만든 값이고 실제 데이터가 아니다.

사용자나이성별최근 7일 클릭 수광고 종류클릭 여부
A25여성5화장품?

  • 샘플: 표의 한 행. 여기서는 사용자와 광고 한 쌍이다.
  • 속성 (attribute): 표의 열. 나이, 성별, 최근 7일 클릭 수, 광고 종류.
  • 학습: 클릭 여부를 아는 과거 행(B, C, D 같은)으로 트리를 만드는 일.
  • 추론: 클릭 여부를 모르는 새 행(A)에 답을 내는 일. Tahoe 논문이 빠르게 하려는 대상이 이 추론이다.

트리 하나가 하는 일

결정 트리 하나는 속성을 묻는 질문을 위에서 아래로 이어 간다. 질문 하나가 노드 하나이고, 답에 따라 왼쪽이나 오른쪽으로 내려간다. 맨 아래 leaf에 예측값이 적혀 있다.

트리 예시
사용자 A의 경로(주황): 나이 25 → 예, 최근 클릭 5회 → 아니오 → 예측 0.15

트리는 "나이 트리", "성별 트리"처럼 속성 하나씩을 맡지 않는다. 위 트리 하나가 나이, 최근 클릭 수, 성별을 모두 묻는다. 트리 하나가 그 자체로 작은 예측기다.

그런데 트리 하나는 정확도가 낮다. 질문 몇 개로 사용자를 거칠게 나눌 뿐이고, 학습 데이터가 조금만 달라져도 질문이 크게 바뀐다. 그래서 서로 다른 트리를 여러 개 만들어 합친다. 트리를 서로 다르게 만드는 방법은 random forest와 GBDT 두 가지다.

random forest: 따로 학습한 트리의 평균

random forest는 트리를 서로 독립으로 학습한다. 트리마다 학습 데이터에서 행을 무작위로 뽑고, 질문에 쓸 속성 후보도 무작위로 일부만 준다. 재료가 다르니 트리마다 질문과 순서가 달라진다.

같은 사용자 A를 트리 3개에 넣으면 이렇게 된다.

  • 투표: 트리마다 "클릭" 또는 "안 함" 중 하나를 내고 많은 쪽을 택한다. 분류 문제에서 쓴다.

트리 하나하나는 틀릴 수 있지만 틀리는 방향이 서로 다르다. 여러 개를 평균하면 그 오차가 서로 상쇄된다. 그래서 random forest가 트리 하나보다 정확하다.

GBDT: 앞 트리의 오차를 고치는 트리의 합

GBDT(gradient boost decision trees)는 트리를 순서대로 학습한다. 두 번째 트리는 첫 번째 트리가 틀린 만큼을 맞히도록 학습하고, 세 번째 트리는 그래도 남은 오차를 맞히도록 학습한다. 그래서 각 트리의 leaf에는 확률이 아니라 더하거나 뺄 보정값이 적힌다.

추론할 때: 트리마다 leaf의 보정값을 읽어 더한다

시작값은 0.10이다. 학습 데이터 전체의 평균 클릭률을 쓴다. 사용자 A를 트리 3개에 차례로 넣으면 트리마다 leaf 하나에 도달하고, 그 leaf에 적힌 값이 그 트리의 보정값이다.

+0.04는 계산해서 나온 값이 아니다. 트리 2에서 A가 도달한 leaf에 학습 때 미리 적어 둔 값이다. 추론은 leaf를 찾아가 적힌 값을 읽고 더하는 일만 한다.

학습할 때: leaf의 값은 남은 오차에서 나온다

그러면 leaf의 값은 어떻게 정해지는가. 2절의 사용자 B, C, D는 클릭 여부를 알고 있으므로, 지금까지의 예측이 얼마나 틀렸는지 계산할 수 있다. 위 트리 1에 세 사용자를 넣으면 B는 +0.05, C는 −0.05, D는 +0.05를 받는다.

사용자① 실제 클릭② 트리 1까지의 예측
(시작값 + 트리 1)		③ 남은 오차
(① − ②)		④ 트리 2의 보정값
(③ × 0.4)		⑤ 트리 2까지의 예측
(② + ④)		⑥ 남은 오차
(① − ⑤)
B00.10 + 0.05 = 0.150 − 0.15 = −0.15−0.15 × 0.4 = −0.060.15 − 0.06 = 0.090 − 0.09 = −0.09
C00.10 − 0.05 = 0.050 − 0.05 = −0.05−0.05 × 0.4 = −0.020.05 − 0.02 = 0.030 − 0.03 = −0.03
D10.10 + 0.05 = 0.151 − 0.15 = +0.85+0.85 × 0.4 = +0.340.15 + 0.34 = 0.491 − 0.49 = +0.51

D의 줄을 따라가 보자. D는 실제로 클릭했으므로 정답이 1이다. 트리 1까지의 예측은 0.15라서 0.85만큼 모자란다. 트리 2는 이 모자란 양을 채우도록 학습하는데, 전부가 아니라 0.4배인 0.34만 leaf에 적는다. 그 결과 예측이 0.49로 올라가고 남은 오차는 0.51로 줄어든다. B와 C는 정답이 0인데 예측이 0보다 커서, 같은 방법으로 값을 뺀다.

  • leaf에 적는 값: 그 leaf에 모인 학습 사용자들의 남은 오차 평균 × learning rate. 이 예시에서는 B, C, D가 트리 2에서 서로 다른 leaf로 가므로 평균이 각자의 오차와 같고, learning rate는 0.4로 정했다.
  • 0.4를 곱하는 이유: 오차를 한 번에 다 메우면 학습 데이터에만 맞는 모델이 된다. 조금씩 고치고 트리를 여러 개 쌓는다.
  • A가 받은 +0.04: A가 간 leaf(여성, 30세 미만)에는 B, C, D가 없다. 표에 없는 다른 학습 사용자들의 오차에서 같은 방법으로 나온 값이다.

트리 3은 ⑥ 열을 목표로 같은 일을 한 번 더 한다. 트리를 더할 때마다 남은 오차가 줄어든다.

이 절의 트리와 수치, learning rate 0.4는 흐름을 보이려고 만든 예시다. 실제 GBDT는 분류 문제에서 합산값을 확률로 바꾸는 함수를 마지막에 한 번 거치는데, 여기서는 생략했다.

추론만 보면 둘은 같다. 샘플 하나가 모든 트리를 한 번씩 내려가고, 트리별 값을 하나로 합친다. 평균도 합산한 뒤 나누는 것이므로 GPU가 하는 일은 같다. Tahoe가 두 종류를 구분하지 않고 한 엔진으로 다루는 이유다.

트리 모양 서술은 논문 8절의 일반적인 설명이다. 논문 실험(Table 2)에서는 random forest인 Higgs가 트리 3000개에 깊이 8, GBDT인 gisette가 트리 20개에 깊이 20이어서 이 경향과 꼭 맞지는 않는다. 트리 수와 깊이는 학습할 때 사람이 정하는 값이다.

Tahoe 논문과의 연결

앞의 예시를 GPU 추론으로 옮기면 논문이 말하는 세 가지 문제가 그대로 보인다.

앙상블의 성질GPU에서 생기는 일논문의 한계
트리마다 묻는 속성과 순서가 다르다 (4절의 트리 1, 2, 3)thread마다 다른 트리를 맡으면 읽는 노드 주소가 흩어진다(a) 병합되지 않는 메모리 접근
최종 예측은 모든 트리의 값을 합쳐야 나온다 (평균, 합산)트리를 thread가 나눠 맡으면 결과를 모으는 reduction이 샘플마다 필요하다(b) 높은 reduction 오버헤드
트리마다 깊이가 다르다 (무작위 속성 선택, 가지치기)깊은 트리를 맡은 thread가 더 오래 일하고 나머지는 기다린다(c) thread 간 부하 불균형

Tahoe의 노드 재배치가 쓰는 "간선 확률"도 이 예시로 설명된다. 트리 1의 루트 질문 "나이 < 30"에 학습 데이터의 80%가 "예"로 갔다면 왼쪽 간선의 확률이 0.8이다. 추론 때도 대부분의 샘플이 그쪽으로 내려갈 것이므로, 그 방향의 노드를 메모리에서 붙여 두면 여러 thread가 한 번에 읽는다.

확인 문제와 점검

문제 1. 트리 100개짜리 random forest에서 "나이"를 묻는 노드는 트리 하나에만 있는가

아니다. 트리마다 여러 속성을 묻고, 같은 속성이 여러 트리에 나올 수 있다. 한 트리 안에서도 임계값을 바꿔 여러 번 나올 수 있다.

문제 2. GBDT에서 트리 3의 leaf에 적힌 −0.01은 무슨 뜻인가

트리 2까지 더한 예측이 조금 높았으니 0.01을 빼라는 보정값이다. 그 leaf만으로는 예측이 되지 않고, 시작값과 앞 트리의 값에 더해야 최종 예측이 된다.

문제 3. 샘플 100만 개를 트리 2000개짜리 포레스트로 추론하면 트리를 몇 번 내려가는가

100만 × 2000 = 20억 번이다. 추론 처리량이 중요한 이유이고, Tahoe가 GPU 메모리 접근을 줄이려는 이유다.

문제 4. Tahoe 논문에서 GBDT로 학습한 트리 묶음을 forest라고 불러도 되는가

된다. 논문 2절이 ensemble과 forest를 같은 뜻으로 쓴다고 밝혔고, Table 2에도 "Forest type" 열에 GBDT가 들어 있다.
