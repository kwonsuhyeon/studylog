GPU로 결정트리 앙상블을 추론할 때 생기는 문제 세 가지와 각각의 해결책이 이 논문의 전부다. 메모리 접근이 병합되지 않는 문제는 노드 재배치로, 스레드 사이 부하 불균형은 트리 재배치로, 리덕션 비용은 네 가지 추론 전략과 성능 모델로 다룬다.

기존 엔진 FIL(NVIDIA RAPIDS Forest Inference Library)은 트리 구조를 보지 않고 노드를 저장하고 트리를 스레드에 나눠 준다. 저자들은 이 무관심을 성능 문제의 근본 원인으로 본다. Tahoe는 학습 뒤에 계산한 간선 확률(edge probability)로 자주 가는 자식 노드를 왼쪽에 모으고, SimHash와 LSH로 비슷한 트리끼리 메모리에 붙여 둔다. 그다음 shared memory에 샘플을 둘지 포레스트를 둘지, 리덕션을 둘지 없앨지를 네 전략으로 나누고, 배치마다 성능 모델로 가장 빠를 전략을 고른다. 결과는 FIL 대비 높은 병렬 작업 평균 5.31배·3.67배·4.05배, 낮은 병렬 작업 평균 2.34배·1.52배·1.45배(K80·P100·V100)다.

결정트리 추론은 루트에서 리프까지 "속성 \(x_j \lt b_i\)" 비교를 반복하는 경로 따라가기다. 트리마다, 샘플마다 경로가 달라서 GPU 스레드들이 서로 먼 주소를 읽고, 서로 다른 시간에 일을 끝낸다.

트리 추론의 기본 동작은 배경지식 노트 1절에 있다. 각 결정 노드는 속성 번호(attribute index, 예: \(F_1\)), 임계값(예: \(V_{11}\)), 값이 없을 때 따라갈 기본 경로(default path, \(D\))를 담는다 [c04#b003]. 포레스트(forest)는 앙상블(ensemble)과 같은 뜻으로 쓰이고, 랜덤 포레스트(RF)와 GBDT 두 종류를 다룬다.

FIL의 추론 방식 (shared data)

FIL이 쓰는 기준 알고리즘을 원문은 shared data라고 부른다 [c04#b008]. 스레드 블록마다 포레스트 전체를 맡고, 블록 안에서는 트리를 라운드 로빈(round-robin)으로 스레드에 나눈다. 샘플은 shared memory가 꽉 찰 만큼 한 배치를 올린다. 스레드마다 자기 트리로 예측한 뒤 블록 단위 리덕션(blockwise reduction)으로 트리 결과를 합친다. 리덕션은 배경지식 노트 6절에서 다룬다.

However, different GPU threads traverse different trees, and can take different tree paths and access different attributes of input samples during the forest traverse, which causes irregular memory access patterns. Memory accesses from threads tend to be uncoalesced, which leads to poor performance, low hardware utilization and underutilized memory bandwidth. Using an industry-quality inference engine (i.e., FIL in NVIDIA RAPIDS suite [10]) to evaluate decision trees on GPU, we show that the ratio of requested data to total fetched data from global memory is only 27.2%, because of uncoalesced memory accesses.
그러나 GPU 스레드마다 다른 트리를 순회하고, 포레스트를 순회하는 동안 서로 다른 경로를 타며 입력 샘플의 서로 다른 속성에 접근하므로 메모리 접근 패턴이 불규칙해진다. 스레드의 메모리 접근은 병합되지 않는(uncoalesced) 경향이 있고, 그 결과 성능이 낮고 하드웨어 활용률이 떨어지며 메모리 대역폭을 다 쓰지 못한다. 산업 수준의 추론 엔진(NVIDIA RAPIDS의 FIL)으로 GPU에서 결정트리를 평가하면, 병합되지 않는 접근 때문에 전역 메모리에서 가져온 전체 데이터 가운데 실제로 요청한 데이터의 비율이 27.2%에 그친다.

As a result, trees in ensemble have different depths, and threads assigned with different trees to traverse have different workloads. Such workload imbalance across threads causes thread idling and low hardware utilization. Our preliminary work on FIL shows that execution time across threads has up to 10x difference.
그 결과 앙상블 안의 트리들은 깊이가 제각각이고, 서로 다른 트리를 받은 스레드들은 일의 양이 다르다. 이런 스레드 간 부하 불균형은 스레드를 놀게 하고 하드웨어 활용률을 떨어뜨린다. FIL을 대상으로 한 예비 실험에서 스레드 사이 실행 시간은 최대 10배까지 차이가 났다.

27.2%라는 비율은 메모리 병합 접근(memory coalescing)의 효율을 재는 지표다. warp의 32개 스레드가 128바이트 안의 주소를 읽으면 트랜잭션 하나로 끝나고, 흩어지면 여러 번 가져오면서 쓰지 않을 바이트까지 끌어온다(배경지식 노트 4절). 트리 깊이가 다른 이유는 학습 때 속성을 무작위로 고르거나 사후 가지치기(post-pruning)를 하기 때문이다 [c03#b005].

FIL이 부족한 이유

FIL의 reorg 형식은 여러 트리의 같은 위치 노드를 번갈아 저장한다(배경지식 노트 3절). 이 방식은 트리들이 구조가 비슷하고 비슷한 경로로 순회된다고 가정하는데, 두 가정은 자주 깨진다 [c03#b006]. 원문은 트리 구조(tree structure)를 신경 쓰지 않는 설계를 근본 원인으로 꼽는다. 여기서 트리 구조는 깊이 같은 위상(topology)과 함께 "자주 지나가는 공통 경로"까지 포함한다 [c03#b007].

자식 두 개 가운데 방문 확률이 높은 쪽을 항상 왼쪽에 둔다. 그러면 여러 트리의 "자주 가는 노드"가 reorg 형식에서 같은 위치 칸에 모이고, 스레드들이 연속 주소를 읽는다.

간선 확률은 학습이 끝난 뒤 각 간선을 지나간 비율이고, 노드 확률(node probability)은 루트에서 그 노드까지 간선 확률의 곱이다 [c04#b003]. 정의와 손 계산은 배경지식 노트 2절에 있다.

To address the above problem, for each node with two children nodes, we ensure that the left child node always has higher possibility to be visited than the right child. Using this method, nodes that are at different trees (but at the same level of different trees) and have high probability to be visited are placed contiguously, so that they can be accessed by threads in a memory-coalesced way. The above method is implemented by swapping the two children nodes after tree training. [...] The descents of each child node go with the child node, as it is swapped. This method goes from top to bottom of the tree.
이 문제를 풀기 위해 자식이 둘인 모든 노드에서 왼쪽 자식의 방문 확률이 오른쪽보다 항상 높도록 만든다. 그러면 서로 다른 트리의 같은 층에 있으면서 방문 확률이 높은 노드들이 연속으로 놓여, 스레드들이 병합된 방식으로 접근할 수 있다. 구현은 학습이 끝난 뒤 두 자식을 맞바꾸는 것이다. [...] 자식을 바꿀 때 그 자식의 하위 노드도 함께 옮긴다. 이 과정은 트리 위에서 아래로 진행한다.
원문 4.1절 [c06#b006] · p.4

원문의 예 (Figure 1, Tree#2)

In Tree#2, the edge possibility of two children nodes of the root node at the second level is 0.3 and 0.7. The right child node (\(V_{23}\)) has higher possibility to be visited than the left child node (\(V_{22}\)). Hence, the two children nodes are swapped. The descents of \(V_{23}\) (i.e., \(V_{24}\) and \(V_{25}\)) go with \(V_{23}\), as \(V_{23}\) is swapped. After swapping, the node \(V_{25}\) in Tree#2 and node \(V_{14}\) in Tree#1 are placed into contiguous memory space.
Tree#2에서 루트의 두 자식으로 가는 간선 확률은 0.3과 0.7이다. 오른쪽 자식(\(V_{23}\))의 방문 확률이 왼쪽(\(V_{22}\))보다 높으므로 둘을 맞바꾼다. \(V_{23}\)의 하위 노드 \(V_{24}\), \(V_{25}\)도 함께 옮겨 간다. 바꾼 뒤에는 Tree#2의 \(V_{25}\)와 Tree#1의 \(V_{14}\)가 연속된 메모리 공간에 놓인다.

유사도 기반 트리 재배치 (4.2절)

원문 4.2 Similarity-based Tree Rearrangement, Figure 3 · 근거 [c06#b011]~[c06#b024] · p.5~6

트리를 짧은 비트열(SimHash 체크섬)로 요약하고, 비트열을 청크로 나눠 해시 충돌 수(LSH)로 비슷한 트리 쌍을 찾는다. 비슷한 트리를 메모리에 붙여 두고 라운드 로빈으로 스레드에 나누면 스레드끼리 하는 일이 비슷해진다.

원문의 "비슷하다"는 추론할 때 비슷한 경로를 타고 비슷한 속성에 접근한다는 뜻이다 [c06#b011]. 쌍마다 비교하는 기존 방법은 트리 3000개 포레스트에서 최대 19분이 걸려 온라인으로 쓸 수 없다 [c06#b012]. 유사도는 추론이 시작되기 전에 온라인으로 계산하므로, 증분 학습(incremental learning)으로 트리가 바뀌어도 다시 계산할 수 있다.

Our evaluation shows that using pairwise comparison can take up to 19 minutes for a tree ensemble with 3000 trees. Such large overhead is too large for an online solution. [...] In our case, SimHash is used to transform trees to items such that we can compare the similarity of trees, and LSH is used to hash similar items into the same buckets, such that we can group multiple trees with high similarity into the same group.
평가해 보면 쌍별 비교는 트리 3000개인 앙상블에서 최대 19분이 걸린다. 온라인 방법으로 쓰기에는 너무 크다. [...] 여기서 SimHash는 트리를 비교 가능한 항목으로 바꾸는 데 쓰고, LSH는 비슷한 항목을 같은 버킷으로 해시해 유사도가 높은 트리들을 한 그룹으로 묶는 데 쓴다.
원문 4.2절 [c06#b012] · p.5

세 단계 흐름

SimHash와 LSH의 일반 원리는 배경지식 노트 8절·9절에서 다룬다. 그림 안의 T_nodes, L_hash, M은 아래 기호표의 \(T_{nodes}\), \(L_{hash}\), \(M\)과 같다.

In this step, we first transform each token into a \(1 \times L_{hash}\) string using a hashing algorithm (SHA1 [16]) [...]. We multiple each string with a weight which is the node probability of the last node in the token transformed to that string. [...] After that, all strings of a tree are added to generate a new string, which is the SimHash result of that tree. We name the SimHash result checksum in the rest of the discussion.
이 단계에서는 먼저 해시 알고리즘(SHA1)으로 각 토큰을 \(1 \times L_{hash}\) 문자열로 바꾼다 [...]. 각 문자열에 가중치를 곱하는데, 가중치는 그 토큰의 마지막 노드의 노드 확률이다. [...] 그다음 트리의 모든 문자열을 더해 새 문자열을 만들고, 이것이 그 트리의 SimHash 결과다. 이후 이 결과를 체크섬(checksum)이라 부른다.

적응형 포레스트 형식 (4.3절)

원문 4.3 Adaptive Forest Format · 근거 [c06#b026] [c06#b027] · p.6

reorg 형식의 틀(모든 트리의 루트 먼저, 그다음 층마다 번갈아 저장)은 그대로 두고 세 가지를 바꾼다. 루트 순서는 트리 재배치 결과로, 자식 좌우는 노드 재배치 결과로 정하고, 속성 번호는 필요한 만큼의 비트만 쓴다.
The format stores the roots of all trees first (as the traditional reorg format). Different from the traditional format that place roots randomly, we decide which roots should be placed close to each other according to the results of similarity-based tree rearrangement. After the roots, we decide whether the order of left and right child nodes of each root should be switched, based on the probability-based node rearrangement.
이 형식은 기존 reorg 형식처럼 모든 트리의 루트를 먼저 저장한다. 루트를 무작위로 두는 기존 형식과 달리, 어떤 루트끼리 가까이 둘지는 유사도 기반 트리 재배치 결과로 정한다. 루트 다음에는 확률 기반 노드 재배치에 따라 각 루트의 왼쪽·오른쪽 자식 순서를 바꿀지 정한다.

공통 식 (1)~(3)

$$ T = T_{\text{SMEM}} + T_{\text{GMEM}} + T_{\text{B\_REDU}} + T_{\text{G\_REDU}} \tag{1} $$ $$ T_{\text{B\_REDU}} = \text{B\_rate} \times \text{Num\_of\_threads} \,/\, N_{batch} \tag{2} $$ $$ T_{\text{G\_REDU}} = \text{G\_rate} \times \text{Num\_of\_thrd\_blocks} \,/\, N_{batch} \tag{3} $$

블록 리덕션 시간은 블록 안 스레드 수에, 전역 리덕션 시간은 블록 수에 비례한다고 본다. 둘 다 샘플 하나에 돌아가는 몫을 구하려고 \(N_{batch}\)로 나눈다 [c08#b009] [c08#b011]. 서재 덤프에는 식 (3)이 두 번([c08#b014], [c08#b016]) 들어 있는데 같은 식이다.

전략별 식 (4)~(7)

shared data (적응형 포레스트 형식 사용). 샘플을 shared memory에 쓰고 거기서 속성을 읽는다. 포레스트는 전역 메모리에서 절반 대역폭으로 읽는다. \(T_{\text{G\_REDU}}=0\)이고 블록 리덕션은 식 (2)를 쓴다 [c08#b020]~[c08#b022].

$$ T_{\text{SMEM}} = \frac{S_{sample}}{\text{BW\_WSMEM}} + \frac{D_{tree} N_{trees} S_{att}}{\text{BW\_RSMEM}}, \qquad T_{\text{GMEM}} = \frac{S_{sample}}{\text{BW\_R}^{\text{COA}}_{\text{GMEM}}} + \frac{D_{tree} N_{trees} S_{node}}{\text{BW\_R}^{\text{COA}}_{\text{GMEM}}/2} \tag{4} $$

direct. shared memory도 리덕션도 없다. 포레스트는 절반 대역폭, 샘플 속성은 병합 없는 대역폭으로 전역 메모리에서 읽는다 [c08#b023]~[c08#b025].

$$ T_{\text{GMEM}} = \frac{D_{tree} N_{trees} S_{node}}{\text{BW\_R}^{\text{COA}}_{\text{GMEM}}/2} + \frac{D_{tree} N_{trees} S_{att}}{\text{BW\_R}^{\text{NCOA}}_{\text{GMEM}}} \tag{5} $$

shared forest. 리덕션이 없다. 포레스트를 shared memory에 올리는 시간은 반복 사용으로 분산되므로 무시한다. 포레스트는 shared memory에서, 속성은 전역 메모리에서 병합 없이 읽는다 [c08#b026].

$$ T_{\text{SMEM}} = \frac{D_{tree} N_{trees} S_{node}}{\text{BW\_RSMEM}}, \qquad T_{\text{GMEM}} = \frac{D_{tree} N_{trees} S_{att}}{\text{BW\_R}^{\text{NCOA}}_{\text{GMEM}}} \tag{6} $$

splitting shared forest. shared forest와 같되 \(N_{batch}\)개 샘플마다 포레스트를 다시 올리고(무시하지 못함) 전역 리덕션을 한다. 포레스트를 올리는 항(각 식의 첫 항)만 \(N_{batch}\)로 나눈다 [c08#b029]~[c08#b031]. 전역 리덕션은 식 (3)이다.

$$ T_{\text{SMEM}} = \frac{N_{nodes} N_{trees} S_{node}}{\text{BW\_WSMEM}\cdot N_{batch}} + \frac{D_{tree} N_{trees} S_{node}}{\text{BW\_RSMEM}}, \qquad T_{\text{GMEM}} = \frac{N_{nodes} N_{trees} S_{node}}{\text{BW\_R}^{\text{COA}}_{\text{GMEM}}\cdot N_{batch}} + \frac{D_{tree} N_{trees} S_{att}}{\text{BW\_R}^{\text{NCOA}}_{\text{GMEM}}} \tag{7} $$
